# جرد البوفيه V1.1
برنامج مستقل عن برنامج المبيعات. يبدأ بـ29 صنفًا حقيقيًا موزعة على خمس فئات، دون أي صنف بلا فئة. جميع العبوات والكميات والأسعار فارغة.

## التشغيل
ارفع محتويات المجلد إلى GitHub Pages أو استضافة HTTPS. افتح index.html من رابط الاستضافة. يحتفظ البرنامج ببياناته محليًا في المتصفح؛ لا تمسح بيانات المتصفح دون تصدير نسخة احتياطية. المزامنة السحابية اختيارية وتحتاج مشروع Supabase منفصلًا، مع تنفيذ ملف supabase_schema.sql وضبط بيانات الاتصال من داخل التطبيق.

## وظائف
- سطر واحد لكل عبوة، اختيار العبوة، إدخال الكمية والسعر، حساب الإجمالي تلقائيًا، إضافة عبوة، وحذف سطر بتأكيد.
- الجرد السابق، المقارنة، تعديل جرد سابق، تصدير Excel، نسخ احتياطية.
- لا يوجد استيراد أصناف أو بيانات تجريبية في الواجهة.
- لا تتصل هذه النسخة بقاعدة بيانات البوفيه الأصلي.

## ملاحظة
هذه حزمة تنفيذ محلية مستقلة، لم يتم نشرها تلقائيًا على GitHub أو إعداد Supabase الخاص بها.


## تحديث V1.2 — صافي الربح
- تبويب مستقل لصافي الربح.
- قيمة المخزون من آخر جرد محفوظ (أو المسودة عند عدم وجود جرد محفوظ).
- بنود يدوية قابلة للجمع والطرح والإضافة والحذف: حساب الضباط، المحفظة، الكاش، الدين، رأس المال.
- تكلفة الضيافة للعرض فقط لأنها خُصمت بالفعل من قيمة المخزون، فلا تُطرح مرتين.
- الأرقام الافتراضية في شاشة الربح فارغة، ولا توجد أي صلة مالية ببرنامج البوفيه الأصلي.
- البيانات محفوظة محليًا مع الجرد، وتدخل ضمن النسخ الاحتياطية والمزامنة اليدوية الاختيارية.
- عند حدوث سحوبات شخصية أو إضافات رأس مال يجب تسجيلها يدويًا كبنود ملائمة.

## V1.3 — ربط السحابة
- إنشاء مشروع Supabase مستقل باسم Gard ElBuffet مع RLS وRPC آمن.
- إعداد الاتصال بالسحابة داخل البرنامج تلقائيًا؛ يحتاج تسجيل حساب بإيميل وكلمة مرور ثم الضغط على «مزامنة الآن».
- البيانات لا تنتقل تلقائيًا؛ يتم رفعها وتنزيلها يدويًا.
- **مهم:** رفع الملفات إلى GitHub لم يتم بسبب عدم توفر إذن الكتابة للربط الحالي (403).
- اختبر المزامنة بحساب تجريبي قبل الاعتماد عليها للبيانات الحقيقية.

## إصلاح 1.3.1
زر (+) يضيف سطر تعبئة جديد فارغ، وتختار الوحدة وتدخل الكمية والسعر بنفسك. لا يغيّر السطر السابق.


## تصفير الجرد بالكامل
من «مزامنة» اضغط «إعادة ضبط المصنع (29 صنف)»، ثم وافق على التأكيدين. تعود الفئات الخمسة والـ29 صنف الأصلية، مع وحدات وكميات وأسعار فارغة وجرد سابق فارغ وصافي ربح فارغ. إذا كنت مسجلاً بحساب الجرد، يلزم الإنترنت وسيُصفّر نفس حساب الجرد على السحابة كذلك؛ لا يمس هذا برنامج المبيعات. إن لم تكن مسجلاً، يتصفّر الجهاز فقط، وعند المزامنة لاحقاً قد يتطلب الأمر حل تعارض مع بيانات سحابية قديمة. البرنامج يحفظ نسخة محلية قبل التصفير.


## إصلاح Safari V1.3.3
إذا كانت بيانات المتصفح المحلية تحتوي على صفر أصناف، ولا يوجد أي جرد سابق أو مسودة بها صفوف، يعيد البرنامج الـ29 صنف والـ5 فئات تلقائيًا. لا يغيّر أي جرد قائم أو قاعدة بيانات البوفيه الأصلية. التخزين في Safari والتطبيق المثبّت منفصل، والمزامنة اليدوية مطلوبة لتبادل البيانات.


## V1.4.0: ربط الجهاز مرة واحدة
- تسجيل دخول مرة واحدة مع حفظ جلسة Supabase وتجديدها تلقائيًا أثناء الاتصال. قد تحتاج تسجيل الدخول مجددًا إذا انتهت صلاحية refresh token أو مسحت بيانات الجهاز.
- مزامنة يدوية فقط عند الضغط على «مزامنة الآن». يظل تسجيل الدخول محفوظًا، والبيانات تبقى محلية عند انقطاع الشبكة.
- تعارض التعديل من جهازين لا يتم حله تلقائيًا بالكتابة فوق البيانات؛ تظهر شاشة الاختيار.
- تحديث Service Worker بأسلوب network-first لملفات الصفحة والكود لمنع بقاء Safari على نسخة قديمة عند توفر الشبكة.
- Safari والتطبيق المثبت قد يكون لكل منهما مخزن محلي مستقل؛ المزامنة عبر الحساب الواحد تربطهما بعد تسجيل الدخول في كل واحد مرة واحدة.


## V1.4.1 — مزامنة يدوية فقط
تم إلغاء كل مؤقتات وأحداث المزامنة التلقائية (عند التعديل وفتح البرنامج وعودة الإنترنت)، مع استمرار حفظ تسجيل الدخول وتجديد الجلسة عند طلب المزامنة يدويًا.
